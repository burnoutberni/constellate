## 2026-02-07 - Stored XSS in ActivityPub Ingress
**Vulnerability:** Incoming ActivityPub activities (Create Note, Create Event) stored HTML content (content, summary) directly in the database without sanitization. Malicious actors could inject scripts (Stored XSS) that would be executed when other instances or clients rendered this content, if they relied on the sender to sanitize or failed to sanitize on output.
**Learning:** Federated protocols like ActivityPub involve accepting content from untrusted remote servers. Treating this content as trusted and storing it raw creates a high risk of Stored XSS, especially since the content often contains HTML (rich text).
**Prevention:** Always sanitize user-generated content, especially HTML, at the ingress point (before storage) using a strict allowlist (e.g., DOMPurify). This provides a defense-in-depth layer, protecting the application even if output encoding is missed in some places. Use `sanitizeHtml` for rich text and `sanitizeText` for plain text fields.
